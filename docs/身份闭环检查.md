# 身份闭环检查报告

> 检查对象：`D:/Work/Library Management`（Flask + SQLite，routes → service → repository 三层）
> 检查日期：2026-10-12（第 12 批完成后）
> 检查方法：**逐身份**把「谁 → 从哪里开始 → 经过什么 → 数据落在哪 → 结果回到谁」这条链路在代码里走通一遍，
> 每一步都落到具体的路由 / 数据表 / 前端节点；走不通的记为**断链**，并区分「缺陷」与「有意不做」。

## 0. 结论速览

| 身份 | 闭环条数 | 闭合 | 人工衔接（不算断链） | 有意不做 | 缺陷 |
|---|---|---|---|---|---|
| 访客（未登录） | 5 | 4 | 1（初始密码靠馆员告知） | 3 | 0 |
| 读者 | 9 | 9 | 0 | 0 | 0 |
| 流通馆员 | 9 | 9 | 0 | 0 | 0 |
| 系统管理员 | 4 | 4 | 0 | 1（参数配置无 UI） | 0 |

**第 12 批修掉的三处真断链**（此前属于「声明了但没生效」「有数据没入口」「有动作没出口」）：

1. **读能力声明后未在路由强制** —— `dashboard:read` 等读能力发给角色却没人检查，实际「登录即全读」。
2. **审批动作有出口没入口** —— 罚金减免超阈值后只能直接生效，没有「提交审批、由他人批准」的载体。
3. **运维动作有数据没出口** —— 后台扫描只在日志里留痕、备份只能手动拷文件、邮件只有站内一条渠道。

## 1. 访客（未登录）· 门户 `/`

| # | 闭环链路 | 起点 | 终点（结果回到谁） | 状态 |
|---|---|---|---|---|
| V1 | 找书 | `GET /api/public/search` 检索 | 图书详情弹窗（含馆藏位置与可借册数） | ✅ 闭合 |
| V2 | 看公告 | `GET /api/public/overview` | 门户公告栏（只出「已发布且在生效窗口内」） | ✅ 闭合 |
| V3 | 看架位 | 同上 → `locations[]` | 分布导览卡片 → 点击跳转筛选 | ✅ 闭合 |
| V4 | **办证** | 提交预登记 → 拿 `AC` 编号 | 凭「编号 + 手机号」查进度 → 通过后显示**证号** + 提示到馆领取 | ✅ 闭合（见下方人工衔接） |
| V5 | 借阅速查 | `POST /api/public/quick-check`（条码/手机号 + 密码） | 脱敏概览与在借明细（只读、不建会话） | ✅ 闭合 |

**人工衔接（设计使然，不是断链）**：发证时馆员会拿到一次性明文 `initial_password`（= 证号后 6 位），
必须当场告知读者；读者首次登录会被**强制改密**（`must_change_password` 闸门）。
密码若中途丢失，走馆员「重置密码」即可恢复——**有补救路径**，所以算闭合而非断链。

**有意不做（写操作必须有会话归属）**：未登录预约、未登录续借、未登录挂失、门户自助发证。
理由：这些动作要落到「谁的责任」上，免登录无法确定归属。

## 2. 读者 · 个人中心 `/reader`

| # | 闭环链路 | 关键节点 | 状态 |
|---|---|---|---|
| R1 | 借阅 | 借出 → 到期前提醒 → 自助续借（未逾期/未达上限/未挂失/未冻结）→ 归还 | ✅ 闭合 |
| R2 | 预约 | 检索 → 排队（有可借复本时不开放）→ 到书通知 → 柜台借出结单 | ✅ 闭合 |
| R3 | 预约改约 | 关旧单（转「已取消」）+ 开新单 → 排队位次按新书重算 | ✅ 闭合 |
| R4 | 预约过期 | 保留期到（`LIBRARY_RESERVATION_HOLD_DAYS`）→ 自动转 `expired` → **回补队列** + 给本人发「预约已过期」→ 让位下一位 | ✅ 闭合 |
| R5 | 滞纳金 | 逾期 → 通知 → 查明细 → 单笔/一次结清（自助）或馆员代收 → 结清后不再计入 | ✅ 闭合 |
| R6 | 挂失 | 一键挂失 → 拦借书/续借/预约（放行查看）→ 自助解挂 → 恢复 | ✅ 闭合 |
| R7 | 消息 | 四类业务事件 + 馆员通知 + 审核结果 → 通知中心（未读角标 / 已读 / 跳转）| ✅ 闭合 |
| R8 | 资料自助 | 改手机号（唯一性校验）/ 邮箱 / **邮件订阅开关** → 回写档案 → 页面即时刷新 | ✅ 闭合 |
| R9 | 互动与变更 | 书评 / 荐购 / 资料变更申请 → 馆员审核 → **回写或驳回** → 结果发回读者消息中心 | ✅ 闭合 |

**边界（有意）**：账号被冻结仍可登录看历史，但不能续借 / 预约；越权访问他人记录一律 403。

**第 12 批新增**：R5 的**大额减免转审批**（馆员提交 → 管理员批准才生效）、R7/R8 的**邮件出站与订阅开关**。

## 3. 流通馆员 · 后台 `/admin`

| # | 闭环链路 | 关键节点 | 状态 |
|---|---|---|---|
| L1 | 借还 | 扫码/检索借书 → **打印借书凭证** → 还书（自动结算罚金）→ 批量还书（逐条独立事务）| ✅ 闭合 |
| L2 | 催还 | 逾期清单 → 批量催还（按「借阅 + 应还日期」幂等）→ **打印催还单**（含逾期天数与滞纳金）→ 读者消息中心收到 | ✅ 闭合 |
| L3 | 罚金 | 代收（可部分收款）/ 减免（理由必填 + 二次确认，超阈值转审批）| ✅ 闭合 |
| L4 | 赔偿 | 登记（同一借阅仅一张待结案）→ 结案（可选按丢失：总册数 -1、库存按不变式重算；可选同步减免罚金）→ 可注销 | ✅ 闭合 |
| L5 | 盘点 | 开单（快照应盘）→ 逐行录实盘（即时差异）→ 关闭冻结 → **先全量校验再调账** | ✅ 闭合 |
| L6 | 采编 | 到货登记（不进馆藏）→ 验收：同 ISBN 加册 / 新 ISBN 建档并分配条码 → 驳回必填原因 | ✅ 闭合 |
| L7 | 批量导入 | 下载模板 → 预览逐行报错 → 正式导入（逐行独立事务）| ✅ 闭合（**第 12 批新增 .xlsx 入口**）|
| L8 | 审核三类 | 办证申请（通过即建档发证）/ 书评（置顶/隐藏）/ 荐购与资料变更（结论必附答复）| ✅ 闭合 |
| L9 | 读者附件 | 上传（魔数嗅探 + 白名单 + 大小限制）→ 预览/下载（鉴权、无公开直链）→ 删除同步清磁盘 | ✅ 闭合 |

**边界（设计使然）**：馆员无 `account:manage` / `log:read` / `approval:approve`（不能管账号、看不到全量日志、不能自批自己的减免申请）。

## 4. 系统管理员 · 后台 `/admin`

| # | 闭环链路 | 关键节点 | 状态 |
|---|---|---|---|
| A1 | 账号 | 建号（选角色）→ 改角色/启停用/重置密码 → 三道守卫（不能操作自己、最后一个在职管理员不可停用降级删除、用户名不与读者证号手机号重名）| ✅ 闭合 |
| A2 | 审计 | 每一次后台写操作与登录登出 → `operation_logs`（谁/何时/对哪条/做了什么/来源 IP）→ 按条件筛选查询 | ✅ 闭合 |
| A3 | **审批**（第 12 批） | 馆员提交超阈值减免 → 工单入 `approvals` → 管理员通过（**同事务执行减免**）/ 驳回（意见必填）→ 状态与执行结果回到工单 | ✅ 闭合 |
| A4 | **运维**（第 12 批） | 调度：本轮计数写入 `job_runs` → 页面看最近执行 → 可手动触发；邮件：渠道状态 + 队列统计 + 测试发信 + 失败重试；备份：一键快照 / 列表 / 下载 / CLI 恢复 | ✅ 闭合 |

**有意不做**：系统参数（借期、罚金、扫描间隔）仍只能改 `.env` 后重启，不做后台配置界面——
参数是「部署决策」而非「日常操作」，做成界面会鼓励随手改运行中的策略，反而危险。

## 6. 仍然存在的断链与「有意不做」（如实列出）

### 6.1 有实际影响，但本阶段不做

| # | 断链 | 为什么现在不做 | 影响 |
|---|---|---|---|
| 1 | **初始密码只靠人工传递** | 无短信 / 邮件下发能力（发证时邮件渠道可能都没配）| 馆员必须当场告知；丢失走重置密码 |
| 2 | **无在线支付** | 需要支付网关与对账，不是应用层能补的 | 滞纳金只能线下收款 + 系统登记 |
| 3 | **无分馆 / 多租户** | 需给全部业务表加 `branch_id` 并改造权限、统计、预约队列 | 单库单馆；只有 `位置` 文本维度 |
| 4 | **无按册条码台账** | `total_copies` 是计数而非逐册记录 | 盘点能定位到「哪本书少几册」，定不到具体某一册 |
| 5 | **无 MARC / 联机取书目** | 需要外部书商 / 图书馆数据源 | 采编仍要手填书名等书目信息 |
| 6 | **服务端 PDF 未做** | 打印走浏览器打印对话框（`#printLayer` + `@media print`）| 纸张适配依赖浏览器设置 |
| 7 | **邮件只记 SMTP 错误** | 退信 / 送达回执需要收信通道 | 只知道「投递动作执行了」，不知道「对方是否读到」 |
| 8 | **审批流只覆盖罚金减免** | 赔偿结案、资料变更目前是「单人即可处理」| 小馆够用；要严格内控需接入更多审批类型 |
| 9 | **无国际化 / 深度无障碍** | 界面全中文硬编码，全面 i18n 与无障碍改造收益 / 成本比在本阶段偏低 | 仅做了基础 aria |

### 6.2 有意不做（设计选择，不是缺陷）

- **未登录的预约 / 续借 / 挂失**：写操作必须有会话归属。
- **门户自助发证**：借书证承载借阅权与责任，必须馆员审核后建档。
- **后台可视化改系统参数**：参数属部署决策，改 `.env` 重启比「运行中随手改」安全。
- **后台在线恢复数据库**：把正在服务的库原地换掉风险极高，恢复只在停服后的 CLI 里做。
