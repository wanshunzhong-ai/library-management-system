# 系统身份功能清单（现状 · 缺口）

> 依据：`library/*/routes.py`、`library/auth/permissions.py`、`templates/index.html`、`templates/reader.html`、`templates/public.html`、`config.py`、`README.md`（截至 2026-10-12 **第 12 批**）。

系统里实际存在 **4 类身份**：访客（未登录）、读者、流通馆员、系统管理员。
后台账号的 `role` 枚举只有两个值：`admin` / `librarian`。

---

## 0. 权限矩阵总览

第 12 批把能力从 **7 项扩到 12 项**，核心变化是**读能力从写能力里拆出来单独声明**：

| 能力（capability） | 说明 | 系统管理员 admin | 流通馆员 librarian |
|---|---|---|---|
| `book:read` | 查图书列表 / 详情 / 盘点单 / 采编单、下载导入模板 | ✅ | ✅ |
| `book:write` | 图书编目与上下架、**盘点**、**采编验收**、**批量导入图书** | ✅ | ✅ |
| `member:read` | 查读者档案 / 办证申请 / 读者互动 / 读者附件 | ✅ | ✅ |
| `member:write` | 读者档案维护、**读者互动审核**（书评 / 荐购 / 资料变更）、**发站内通知**、**读者附件**、**批量导入读者** | ✅ | ✅ |
| `loan:read` | 查借阅 / 预约 / 滞纳金 / 赔偿 | ✅ | ✅ |
| `loan:write` | 借书 / 还书 / 续借 / 预约处理 / 罚金收退、**赔偿处理**、**批量催还** | ✅ | ✅ |
| `announcement:read` | 查公告与开馆时间 | ✅ | ✅ |
| `announcement:write` | 公告与开馆时间维护 | ✅ | ✅ |
| `dashboard:read` | 查看概览报表 | ✅ | ✅ |
| `approval:approve` | **审批中心**：罚金减免超阈值工单的通过 / 驳回 | ✅ | ❌ |
| `account:manage` | 后台账号与授权管理、**系统维护**（调度 / 邮件渠道 / 备份） | ✅ | ❌ |
| `log:read` | 查看操作日志 | ✅ | ❌ |

- 授权按**能力**声明，映射表集中在 `library/auth/permissions.py`，路由用 `@require_permission(...)` 标注。
- **失败即拒绝**：角色不在映射表里 → 空能力集，什么都读不到也写不了。
- 越权尝试写一条 `operation_logs`（状态「已拦截」）。
- 前端按权限隐藏入口（`data-permission`），手改地址栏会被挡回概览；后端独立校验，前端只是"不给入口"。
- **读写分开声明**的理由：只隐藏前端入口、接口却不校验，等于没做权限——抄个 URL 就能把全馆读者名单拉走。
  分开声明也为将来加「只读审计 / 财务岗位」留好了口子（只需给一组 `*:read`）。

第 12 批已把这一课补齐：`dashboard:read` 与各模块的**列表 / 详情读接口**（books / members /
loans / reservations / fines / compensations / stocktaking / acquisitions / member-files /
announcements / applications / engagement）**全部挂上了对应的读能力校验**，第 11 批遗留的
「能登录后台就能读全部数据」不复存在。

## 1. 访客（未登录）· 公共门户 `/`

### ✅ 已有

- 首页：馆名 / 标语 / 开放信息 / 关于（`templates/public.html`）
- **馆藏检索**：书名 / 作者 / ISBN / 条码 + 分类筛选 + 「仅看可借」+ **馆藏位置**（`GET /api/public/search`）
- 馆藏概览统计条 `statbar`（`GET /api/public/overview`）
- 热门推荐 / 新书推荐（`recommendCards` / `newCards`）
- 借阅规则展示（`ruleGrid`，随 `policy` 动态渲染）
- 图书详情弹窗
- 统一登录入口（管理员与读者走同一个登录弹层，两套会话互不顶掉）
- **公告栏**：当前生效的公告（置顶优先、重要高亮、过期自动隐藏）`GET /api/public/overview` → `announcements`
- **开馆时间**：由馆员维护的开馆时间公告覆盖「关于本馆」文案（不再需要改代码）
- **馆藏分布导览**：按位置聚合的架位卡片（可借册数 / 在馆种数 / 主要分类），点击即按该位置筛选检索
- **在线办证预登记**：填资料提交拿 `AC` 编号；凭**编号 + 手机号**查审核进度（通过后显示证号）
- **免登录借阅速查**：凭条码 / 手机号 + 密码看脱敏概览与在借明细（只读、不建会话、复用登录限流）

### ❌ 缺失

| 缺口 | 说明 |
|---|---|
| 预约 / 续借仍需登录 | 写操作必须有会话归属，免登录下无法确定「这单算谁的」，**有意不做** |
| 办证不做自助发证 | 借书证承载借阅权与责任，必须馆员审核后建档；门户只做**预登记** |
| 证件附件上传 | 申请只存证件号**后四位**（隐私最小化），无法上传证件照片 |
| 到馆取书预约 | 未登录不能占坑（同「预约需登录」） |
| 无楼层平面图 / 3D 导航 | 只有文字架位聚合卡片，无平面图或指引路径 |
| 无读者自助挂失 | 挂失需登录（写操作） |
| 无开放时间日历 / 节假日例外 | 开馆时间是一段文字说明，不是结构化日历 |

## 2. 读者 · 个人中心 `/reader`

### ✅ 已有

| 模块 | 能力 | 接口 |
|---|---|---|
| 登录 | 证号 / 手机号 + 密码登录、登出 | `POST /api/reader/login` `/logout` |
| 我的借阅 | 在借 / 逾期 / **已还历史**（`status=all\|open\|borrowed\|overdue\|returned`） | `GET /api/reader/loans` |
| **自助续借** | 沿用管理端规则：未逾期、未达上限、未挂失、未冻结 | `POST /api/reader/loans/:id/renew` |
| **我的预约** | 排队中 / 已到书 / 已借出 / 已取消；含排队位次、到书时间；可自助取消 | `GET/POST /api/reader/reservations`、`.../:id/cancel` |
| **预约图书** | 按书名/作者/ISBN/条码检索，对「已借完」的书排队（有可借复本时不开放） | `GET /api/reader/books/search` |
| **滞纳金查询与缴纳** | 逐笔逾期天数 / 应缴 / 已缴 / 待缴；单笔缴纳 + **一次结清**；缴纳历史 | `GET /api/reader/fines`、`POST /api/reader/fines/pay` |
| **借书证挂失** | 一键挂失 / 解除；挂失期拦借书、续借、预约，放行查看 | `POST /api/reader/card/lost` `/unlost` |
| **首次登录强制改密** | 新建 / 重置密码后置位，改密前除 login/logout/me/password 外全部 403（后端闸门 + 不可跳过的遮罩） | `POST /api/reader/password` |
| **站内消息中心** | 铃铛 + 未读角标；全部 / 未读页签；预约到书、逾期、到期前、预约过期、馆员通知、审核结果；单条已读 / 全部已读；卡片可跳转模块（白名单锚点） | `GET /api/reader/notifications`、`.../:id/read`、`.../read-all` |
| **我的书架** | 收藏馆藏 + 私人备注（仅本人可见），可从书架跳检索 / 预约 | `GET/POST /api/reader/favorites`、`PUT/DELETE /api/reader/favorites/:id` |
| **评分与短评** | 对借过且已归还的书打 1–5 星 + 短评；可改（同书同人覆盖）、可删；门户展示聚合且脱敏 | `GET/POST/DELETE /api/reader/reviews`、`.../pending`、`/books/:id/reviews` |
| **荐购登记** | 提交书名 / 作者 / ISBN / 理由，跟踪待处理 / 已采纳 / 已采购 / 未采纳与答复 | `GET/POST /api/reader/book-requests` |
| **资料变更申请** | 申请改姓名 / 读者类型（走馆员审核），同字段单一待审 | `GET/POST /api/reader/profile-requests` |
| **电子借书证** | 可扫描二维码（QR Model 2）+ Code 128 条码，只编码证号，可打印 | 前端 `qrcode.js` / `barcode.js` |
| **导出 CSV** | 借阅记录 / 我的预约 / 我的书架 / 滞纳金 四类，带 BOM 与时间戳 | 前端 `downloadCsv` + 分页取全 |
| **预约改约** | 改约到另一本暂无可借复本的书（关旧单 + 开新单，原单转「已取消」） | `POST /api/reader/reservations/:id/rebook` |
| 个人资料 | 改手机号 / 邮箱（手机号占用校验） | `PUT /api/reader/profile` |
| 修改密码 | 改后强制重新登录 | `POST /api/reader/password` |
| 概览统计 | 在借 / 预约中 / 待缴滞纳金 卡片 + 未读消息数 | `GET /api/reader/me` |

**边界**：账号被冻结仍可登录查看历史，但不能续借 / 预约 / 缴费之外的写操作；越权访问他人记录一律 403。

### ❌ 缺失

| 缺口 | 严重度 | 说明 |
|---|---|---|
| **通知不主动推** | 高 | 站内消息中心已有（预约到书 / 逾期 / 到期前 / 预约过期 / 馆员通知 / 审核结果），且第 11 批补上了**后台扫描线程**（默认 600 秒一轮，不再只靠打开页面时补算）；但**无短信 / 邮件网关**，触达仍止于站内消息 |
| **预约到期释放已可定时** | 低 | 取书保留期 + 倒计时 + 过期自动释放均已有；第 11 批新增 `library/scheduler.py` 后台线程按 `LIBRARY_SWEEP_INTERVAL_SECONDS` 定时执行（0 = 退回纯惰性），**多实例下会重复触发但幂等** |
| 不能改证号 / 可借上限 | 中 | 姓名 / 读者类型已可**申请变更**（走馆员审核）；证号与可借上限仍只能馆员直接维护 |
| 无在线支付 | 中 | 缴纳为**线下收款 + 系统登记**，无支付网关、无电子凭证 |
| 无带签章的电子凭证 | 低 | 已有借阅 / 预约 / 书架 / 滞纳金四类 CSV 导出，但没有带馆方签章的缴费证明 / 借阅证明 |
| 无公开书单 / 收藏夹分享 | 低 | 有「我的书架」（收藏 + 私人备注），但无公开书单、不可分享 |
| 无到馆取书自助登记 | 低 | 到书后仍需到柜台办理借出，无自助取书机接口 |

## 3. 流通馆员 librarian · 后台 `/admin`

能力集：`book:read` + `book:write` + `member:read` + `member:write` + `loan:read` + `loan:write` + `announcement:read` + `announcement:write` + `dashboard:read`（**9 项；不含 `approval:approve` / `account:manage` / `log:read`**）

### ✅ 已有

- **概览报表**：馆藏/可借/在借/逾期/7 天内到期/注册读者 六张卡；借阅趋势折线、分类借阅排行、热门榜、逾期清单、借阅策略展示
- **图书管理**：列表 / 关键词检索 / 分类筛选 / 排序 / 分页 / 详情；新增 / 编辑 / **上下架** / 删除；**导出 CSV**
- **读者管理**：列表 / 检索 / 状态筛选；新增 / 编辑 / 删除 / **重置密码**（会重新置位强制改密标记）/ **导出 CSV**；对单个读者**发站内通知**（标题 + 正文 + 可选跳转模块）
- **借阅管理**：列表 / 检索 / 状态筛选；**借书** / **还书** / **批量还书** / **续借**；**导出 CSV**
- **预约管理**：队列查看 / 状态页签 / 关键词检索 / 分页；**通知到书** / 取消（还书时系统按序自动唤醒队列）
- **罚金**：缴纳流水列表 / 检索；按读者查应缴明细；**代收**（收款）/ **减免**
- **公告管理**：公告与开馆时间维护；状态页签（全部 / 已发布 / 草稿 / 已下线）+ 类型 + 关键词筛选；置顶 / 重要程度 / **生效窗口** / 新建 / 编辑 / 上下线 / 删除
- **办证审核**：门户办证申请的状态页签（待审核 / 已通过 / 已驳回 / 全部）+ 检索；**通过并发证**（可调姓名 / 类型 / 证号 / 上限，事务内建档并返回初始密码）/ **驳回**（必填原因）
- **读者互动**（一个视图，三个页签）：**书评**（全部 / 已发布 / 已隐藏，可置顶 / 隐藏）/ **荐购**（待处理 / 已采纳 / 已采购 / 未采纳，结论必附答复）/ **资料变更**（待审核 / 已通过 / 已驳回，通过即回写档案）；导航带待处理角标 + 顶部三张汇总小卡
- **滞纳金管理**：缴费流水分页（关键词 / 类型筛选 + 收 / 减合计）、按读者查待缴明细；**代收**（可部分收款，缺省 = 结清该笔）/ **减免**（**理由必填** + 前端**二次确认框**）；**导出 CSV**
- **赔偿处理**：丢书 / 损书赔付登记（同一借阅仅一张待结案单）；结案可勾选**按丢失结案**（不回补库存，总册数 -1、可借数按不变式重算）与**同步减免该笔逾期滞纳金**；待结案可注销；**导出 CSV**
- **盘点**：按馆藏位置（留空 = 全馆）开单，单号 `PDYYYYMMDD-NNN`；开单即**快照**应盘册数；同馆位仅一张进行中；逐行录实盘数并即时给出**账实一致 / 盘盈 / 盘亏**与进度、按差异类型筛选；关闭冻结明细（可重新打开补盘）；**调账必须先关闭且先全量校验再写入**（实盘低于在借册数即 422）；进行中可删，已关闭保留作记录
- **采编验收**：到货登记单（书名 / ISBN / 册数 / 单价 / 供应商…，**不进馆藏**）；验收时按 **ISBN 去重——已有则加册、没有则建档并自动分配 `BK` 条码**；驳回必填原因；已验收 / 已驳回保留作采购记录；**导出 CSV**
- **批量导入**：图书 / 读者两大页签，粘贴 CSV、上传 **.csv / .xlsx**（Excel 无需另存），**服务端生成模板**（与解析器同源、带 BOM）；**先预览后写入**，逐行「第 N 行：失败原因」并标红失败行；文件内重复单独提示；**逐行独立事务**；单次上限 1000 行 / 1MB
- **批量催还**：按当前逾期清单（可用关键词 / 读者 / 图书先筛选，或传明确 id）一键给读者发站内催还通知，**按「借阅 + 应还日期」幂等**
- **打印排版**：借书凭证、催还单（一页一张，含逾期天数与滞纳金）、索书号条码书标；借书弹窗可勾选「借出后打印凭证」
- **读者附件**：为读者上传照片与证件影像（JPEG / PNG / WebP / PDF），弹窗内预览 / 下载 / 删除；鉴权下载、无公开直链
- **十一个视图补齐 CSV 导出**：预约管理 / 滞纳金管理 / 赔偿处理 / 采编验收 / 公告管理 / 办证审核 / 操作日志 / 读者互动等
- **减免超阈值自动转审批**（第 12 批）：减免金额达到 `LIBRARY_APPROVAL_WAIVER_THRESHOLD` 时，接口不执行减免，只返回「已提交审批」工单号——**业务数据零改动**，等系统管理员批准。阈值默认 0 = 不启用，行为与历史版本一致

### ❌ 缺失

| 缺口 | 说明 |
|---|---|
| **MARC / ISBN 自动抓取** | 采编验收已能「同 ISBN 加册 / 新建档」，但仍要手填书名等书目信息，没有 978 联机取书目数据 |
| **调拨 / 分馆** | 无馆藏地维度、无分馆授权；只有单一 `位置` 文本（盘点已按位置开单，但不等于分馆权限） |
| **按册台账** | `total_copies` 是计数而非逐册条码台账，盘点只能定位到「哪本书少了几册」，无法定位到具体某一册 |
| **赔偿审批流** | **罚金减免已可走审批**（第 12 批），但赔偿结案仍然直接生效，没有多级审批 |
| **服务端 PDF** | 打印依赖浏览器打印对话框（`#printLayer` + `@media print`），无服务端 PDF 生成与纸张精细适配 |
| **不能审批减免** | 只能「提交」减免工单，批准权在系统管理员（**设计如此**，内控需要） |
| 权限约束 | 不能管理账号、看不到全量日志与系统维护（**设计如此**，非缺陷） |

## 4. 系统管理员 admin · 后台 `/admin`

= 流通馆员全部能力 **＋** 以下三项。

### ✅ 已有

- **账号管理**：列表 / 详情 / 新建（选角色：系统管理员·流通馆员）/ 改姓名 / 改角色 / 启停用 / 重置密码 / 删除
  - 三道守卫：**不能操作自己的账号**、**最后一个在职系统管理员不可被停用·降级·删除**、**用户名不得与读者证号或手机号重名**
- **操作日志**：按关键词 / 操作者类型 / 动作 / 结果 筛选 + 分页；概览聚合；记录每一次后台写操作与登录登出（谁、何时、对哪条、做了什么、来自哪个 IP）；**越权尝试标「已拦截」**
- **审批中心**（第 12 批）：待审批 / 已通过 / 已驳回 / 全部页签 + 关键词检索；工单显示类型、读者、金额、申请人（含申请时间）、申请理由；**通过**在同一事务内立即执行减免并回报实际减免额，**驳回**必须填写审批意见且不改任何业务数据；导航入口带**待审批角标**，已处理工单不再显示动作按钮
- **系统维护**（第 12 批）：三个页签 —— ① **后台任务**：线程状态 / 间隔 / 累计轮数 / 最近一轮耗时与五类计数 + 最近 20 轮留痕，支持**立即执行一轮**；② **邮件渠道**：SMTP 渠道状态（密码不回传）、发件地址、待发 / 已发 / 失败计数与最近 15 条记录，支持**发送测试邮件**与**一键重试失败邮件**；③ **数据备份**：备份列表（大小 / 类型 / 时间 / 各表行数摘要）、**立即备份**（可勾选连附件打 zip）、**下载备份**

### ❌ 缺失

| 缺口 | 说明 |
|---|---|
| **角色不可自定义** | 能力集硬编码在 `permissions.py`；新增「采编」「馆长」「财务」等岗位必须改代码（**读能力已拆出来**，加只读岗位的成本已降低） |
| **密码策略 / 双因素** | 无复杂度、无有效期、无 2FA |
| **登录风控** | 无 IP 白名单、无异地登录告警（有失败次数锁定 5 次 / 5 分钟） |
| **日志导出与归档** | 不能导出、无保留期策略、无冷备归档 |
| **系统参数可视化配置** | `loan_days` / `max_renew` / `fine_per_day` / `fine_cap` / `LIBRARY_APPROVAL_WAIVER_THRESHOLD` 等只能改 `.env` 后重启，后台无配置界面（**只有 SMTP 与备份目录在「系统维护」里可见状态，不能在界面上改**） |
| **在线恢复** | 恢复只有 CLI（`python app.py restore`，须停服）；后台刻意不给在线恢复入口 —— 把正在运行的库原地换掉是自找麻烦 |
| **备份定时化 / 异地备份** | 备份只能手动点或手工调 CLI，无 cron 化的自动备份、无异地 / 云存储同步 |

## 5. 跨身份的系统级缺口（不属于任何单一角色，是整体没有）

第 12 批针对原先的 8 条逐条处置：**5 条已落地、3 条已评估后明确不做**（附原因）。

| # | 缺口 | 第 12 批处置 | 现状 |
|---|---|---|---|
| 1 | **无主动通知渠道** | ✅ **已落地**：SMTP 邮件出站（`LIBRARY_SMTP_*`） + 出站队列 + 渠道状态页 + 测试发信 + 失败重试 + 读者退订开关 | 站内通知之外补齐**邮件**通道；**短信 / 微信 / 钉钉仍未接入**。入队与投递分离：未配 SMTP 时消息停在「待发送」，配好后自动补发不丢数据 |
| 2 | **调度仍是"最朴素线程"** | ✅ **已落地可观测**：`job_runs` 表逐轮留痕（时间 / 触发方式 / 耗时 / 结果 / 异常）、后台可见 + **手动执行一轮** | 调度载体本身仍是 daemon 线程（**有意如此**，见 `library/scheduler.py` 的取舍说明）；已从"黑盒"变成"看得见、点得动"。分布式调度 / 任务队列仍然不做 |
| 3 | **无在线支付** | ❌ **明确不做** | 涉及资金、对账、退款、发票、第三方资质与合规，不是本系统的边界；滞纳金维持「线下收款 + 系统登记」 |
| 4 | **无审批流引擎** | ✅ **已落地（通用、可扩展）**：`approvals` 表 + 审批中心 + 阈值开关 + 通过时才在同一事务内执行 | 目前只接了「罚金减免」一种 `kind`；表结构（`kind` / `entity_id` / `entity_label` / `amount` / `payload`）是通用的，接采购 / 账号申请只需加一个 `kind` 与对应的执行函数 |
| 5 | **无分馆 / 多租户** | ❌ **明确不做** | 单馆场景下引入租户维度会污染每一张表与每一个查询；真要多分馆，正确做法是独立部署 + 共享书目库，而不是在单库里加 `branch_id` |
| 6 | **读接口无能力校验** | ✅ **已落地**：能力从 7 项扩到 12 项，**读写分开**，所有 GET 查询接口逐个挂上 `*:read` | 第 11 批遗留的「登录即全读」已消除；馆员访问审批 / 系统维护接口一律 403（后端强制，不只是隐藏菜单） |
| 7 | **批量通道只覆盖 CSV + 无备份命令** | ✅ **已落地**：零依赖 `.xlsx` 解析接入导入（三种入口共用同一解析链路）+ `app.py backup` / `restore` + 后台备份页 + 迁移文档 | 借阅历史 / 罚金流水**有意不做批量导入**（理由与替代方案见 `docs/历史数据迁移.md` 第 5 节） |
| 8 | **无国际化 / 深测无障碍** | ❌ **明确不做** | 面向单一语种的中小型馆；i18n 需要把所有硬编码文案抽成资源文件并重构前端渲染，收益与成本不成比例。无障碍已做基础 aria（弹窗焦点陷阱 / `aria-busy` / 表格语义），不追 WCAG AA 全项 |

## 6. 一句话结论

- **访客侧**已完成「看得见 + 问得到 + 办得成第一步」：公告与开馆时间、馆藏分布导览、在线办证预登记、免登录借阅速查；**有意不做的**是未登录预约 / 续借——写操作必须有会话归属。
- **读者侧**已形成完整自助闭环（借阅 · 续借 · 预约与改约 · 滞纳金 · 挂失 · **消息中心** · **我的书架** · **评分短评** · **荐购登记** · **资料变更申请** · **电子借书证** · **四类 CSV 导出** · **首次登录强制改密** · **邮件订阅开关**）。第 12 批补上了**邮件订阅开关**后，「主动通知触达」只剩**短信 / 微信**未接；剩下的大缺口是**在线支付**。
- **馆员侧**第 11 批补齐了规模化与专业流程（批量导入 / 赔偿 / 盘点 / 采编 / 批量催还 / 打印 / 附件 / 导出），第 12 批补上了 **.xlsx 导入**与**减免转审批的提交端**；缺口收敛为**「更专业的编目能力」（MARC / 联机取书目）、「按册台账」（逐册条码）、「分馆与调拨」与「服务端 PDF」**。
- **管理员侧**第 12 批补上了**审批中心**与**系统维护**（调度留痕 / 邮件渠道 / 备份下载），加上原有的账号管理与操作日志，「内控 + 运维」两条线已经闭环；剩余缺口集中在**「可配置化」（角色自定义、参数界面、自动备份）与「风控」（密码策略、2FA、日志归档）与「在线恢复」**。
- **权限模型**第 12 批从「写能力 7 项」升级为「读写能力 12 项」，**读接口逐个校验**——「登录即全读」这个最容易被忽视的洞已经堵上。

## 7. 本清单的维护方式

* 新增接口时，**先决定它属于哪个 capability**，再在路由上挂 `@require_permission`——
  这是唯一能防止权限腐化的纪律。
* 改完权限后，跑 `python tests/smoke_test.py`：§34.1 会用「临时把馆员的读能力摘掉 → 断言
  GET 返 403 → 还原 → 断言恢复 200」的方式，把读能力边界钉死。
* 身份闭环的逐条复核结论见 [身份闭环检查](./身份闭环检查.md)。

- **系统级**最该补的三件事：**主动通知渠道**（邮件 / 短信——站内中心与后台扫描线程都已就位，只差外部网关）、**更可靠的调度**（现在的 daemon 线程够用但只适合单实例；多实例应换外部调度）、**配置化与备份**（否则运维全靠改代码）。
