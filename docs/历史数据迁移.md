# 历史数据迁移指南

> 面向：要把**旧系统 / 纸质台账 / Excel 表**里的数据搬进本系统的馆员。
> 适用版本：含第 12 批（.xlsx 导入）之后的所有版本。
> 前置阅读：[PyCharm 部署指南](./PyCharm部署指南.md) 第 0–11 步（系统得先跑起来）。

---

## 0. 一句话结论

**书目档案与读者档案可以批量导入；借阅历史、罚金流水、预约记录不做批量导入。**
后者不是「还没做」，而是有意为之——理由见 [第 5 节](#5-借阅历史为什么不能导进来)。

| 数据 | 能不能导 | 走哪条路 |
| --- | --- | --- |
| 书目（书名/ISBN/作者/出版社/分类/年份/位置/册数/条码/简介） | ✅ 能 | 后台「批量导入」→ 图书导入 |
| 读者（姓名/证号/类型/手机/邮箱/可借上限/状态） | ✅ 能 | 后台「批量导入」→ 读者导入 |
| 公告、开馆时间 | ✅ 能（逐条录） | 后台「公告管理」（量少，不值得做批量） |
| 在借未还的书 | ⚠️ 手工重放 | 后台「借阅管理」逐笔办理（见 [第 5.2 节](#52-必须搬的部分未还清的借阅)） |
| 未缴罚金 | ⚠️ 随借阅产生 | 借阅日期录对，罚金由系统按统一口径自动算出 |
| 历史已还记录 / 已收罚金 / 已结束预约 | ❌ 不导 | 见 [第 5.1 节](#51-不需要搬的部分) |
| 读者照片 / 证件影像 | ⚠️ 逐人上传 | 后台「读者附件」；文件本身无法靠表格迁移 |

## 1. 迁移前必做的三件事

### 1.1 先备份「当前」库

哪怕现在库里只有演示数据，也先备一份——迁移过程中手滑点错，至少能回到起点。

```bash
# 项目根目录下执行（Windows 用 .venv\Scripts\python.exe）
python app.py backup --list          # 看看已有哪些备份
python app.py backup                 # 只备数据库
```

备份落在 `LIBRARY_BACKUP_DIR`（默认是数据库同级目录下的 `backups/`），
文件名形如 `library-20261012-093514.db`，旁边有一份同名 `.json` 摘要
（记录了各表行数，恢复前先看它）。

### 1.2 决定「是迁移还是新建」

* **全新上线**（旧系统停用、数据从零开始）→ 建议**清空演示数据**后再导，
  免得「示例：人类简史」混进真实馆藏。
* **换系统**（旧系统还在跑，要并行一段时间）→ 保留现状，用**真实 ISBN / 证号**导，
  导入会自动跳过/报错重复项，不会把已有数据覆盖掉。

清空演示数据（**只删数据、不删表结构**）：

```bash
# ⚠️ 危险：这条会清掉全部业务数据。执行前务必先 python app.py backup
python - <<'PY'
import sqlite3
from config import get_config
conn = sqlite3.connect(get_config().db_path)
for t in ("loans", "reservations", "fine_payments", "notifications",
          "favorites", "reviews", "member_files", "member_applications",
          "compensations", "stocktaking_items", "stocktaking_batches",
          "acquisitions", "book_requests", "profile_requests",
          "announcements", "outbound_messages", "approvals", "job_runs",
          "operation_logs", "books", "members"):
    conn.execute(f"DELETE FROM {t}")
conn.commit()
print("已清空业务数据；管理员账号保留，默认口令请登录后立即修改。")
PY
```

> 想连管理员一起清掉、完全从头来，最省事的办法是**把数据库文件删掉**再启动
> ——系统会自动建库并重建默认管理员（`LIBRARY_ADMIN_USER` / `LIBRARY_ADMIN_PASSWORD`）。

### 1.3 确认登录账号能进后台

用管理员账号打开 `http://127.0.0.1:8000/admin`。「批量导入」在左侧导航的
**图书** / **读者** 视图里有入口，也可以在地址栏直接进 `#book-import` 区块
（后台是 hash 路由，导航关掉也不影响数据）。

## 2. 图书批量导入

### 2.1 表头（第一行必须是表头）

服务端**中英文表头都能认**，以下别名等价：

| 字段 | 中文表头 | 英文表头 | 其它可识别写法 | 必填 |
| --- | --- | --- | --- | --- |
| 书名 | 书名 | title | — | **是** |
| ISBN | ISBN | isbn | 书号、isbn号 | **是**（唯一键） |
| 作者 | 作者 | author | — | 否 |
| 出版社 | 出版社 | publisher | — | 否 |
| 分类 | 分类 | category | — | 否（默认「未分类」） |
| 出版年份 | 出版年份 | publish_year | 年份、year | 否 |
| 馆藏位置 | 馆藏位置 | location | 位置 | 否 |
| 总册数 | 总册数 | total_copies | 册数、copies | 否（默认 1） |
| 馆藏条码 | 馆藏条码 | barcode | 条码 | 否 |
| 图书简介 | 图书简介 | description | 简介 | 否 |

**列的顺序无所谓**，多出来的列会被忽略。最省事的做法是点页面上的
**「下载模板」**——模板由服务端生成，解析器认哪些表头，模板就写哪些表头，两处不会打架。

### 2.2 三种录入方式（同一套校验）

1. **直接粘贴**：在 Excel / WPS 里框选整块（含表头）→ Ctrl+C → 粘到「粘贴表格内容」框。
   Tab 分隔、逗号分隔都能识别。
2. **上传 .csv**：`另存为 CSV UTF-8（逗号分隔）` 后点「选择文件」。
3. **上传 .xlsx**：直接把 Excel 文件交给「选择文件（.csv / .xlsx）」——**不用另存**
   （第 12 批新增，服务端用标准库解析，不依赖任何第三方库）。

> ⚠️ 只支持 `.xlsx`（Excel 2007+）。老式 `.xls` 会提示「旧版 .xls 请先用 Excel 另存为 .xlsx」。

### 2.3 必须先「预览校验」

点**「预览校验」**，系统只做校验**不写库**，逐行给出结论：

* `校验通过`
* `ISBN xxx 已存在`（与库里已有书目撞了）
* `文件内重复：ISBN xxx 在前面已出现过`（同一份文件里自己撞了）
* `书名不能为空`

把失败的几行改好、重新导一次；或者先正式导入，成功的那批会落库，
失败的行留在结果面板上（标红）供你对照修改。

### 2.4 正式导入

点**「开始导入」**。结果面板每行显示 `已新增（#123）`。
一次最多 **1000 行**，超了会提示拆分。

### 2.5 ISBN 是唯一键——这是条硬规矩

系统用 ISBN 判重（**去掉分隔符、统一大写**后比对：`978-7-5063-6543-7` 与
`9787506365437` 视为同一本）。所以：

* 同一本书有多个副本 → **一行**，把「总册数」写够即可，不要拆成多行。
* 旧书没有 ISBN（内部编号、旧书号）→ 也照原样填，系统只把它当字符串键，
  不强求 13 位（校验位不对只提示、不阻断——见 `library/validation.py::isbn_check`）。
* 真的两本书共用同一个 ISBN（旧台账常见）→ 导入时给其中一本加后缀
  （如 `9787506365437-2`），否则第二行必然被拒。

## 3. 读者批量导入

### 3.1 表头

| 字段 | 中文表头 | 英文表头 | 其它可识别写法 | 必填 |
| --- | --- | --- | --- | --- |
| 姓名 | 姓名 | name | — | **是** |
| 读者证号 | 读者证号 | card_no | 证号、借书证号、card | **是**（唯一键） |
| 读者类型 | 读者类型 | member_type | 类型 | 否（默认「社会」） |
| 手机号 | 手机号 | phone | 电话、手机 | 否（填了就必须唯一） |
| 邮箱 | 邮箱 | email | — | 否 |
| 可借上限 | 可借上限 | max_borrow | 上限 | 否（默认取系统配置，1–50） |
| 状态 | 状态 | status | active | 否（默认 `active`） |

**取值约束**（写错会被逐行拒掉）：

* `读者类型` 只能是 **学生 / 教师 / 社会 / VIP** 之一。
* `状态` 只能是 **`active`（正常） / `frozen`（停用）**，注意是英文小写。
* `可借上限` 是 1–50 的整数。

### 3.2 唯一性：证号与手机号都全局唯一

* **读者证号**唯一——但注意它**同时要和馆员账号名错开**
  （`ensure_identifier_available` 会一起查 `admins.username`）。
* **手机号**唯一且非空才查重：两个读者填了同一个手机号 → 后者被拒；
  留空则不受限（留空 = 没有手机号，多个读者可以同时留空）。
* 证号和手机号**都能当登录账号**（读者端登录时自动识别），所以不能重复。

### 3.3 初始密码 = 证号后 6 位

导入时**不需要也不应该**填密码。系统给每个新读者：

* 初始口令 = **读者证号的后 6 位**（`library/auth/passwords.py::initial_password`）
* 置 `must_change_password = 1` —— 读者第一次登录会被强制改密

> 证号不足 6 位时按实际位数取（如证号 `9001` → 口令 `9001`）。
> 正式启用前，务必让读者**先登录改密**，或者由馆员逐个「重置密码」。

### 3.4 邮箱列的价值

填了邮箱且读者没关闭订阅，「催还 / 到期 / 预约到书」这些通知会**同时**走
站内消息与邮件（需在 `.env` 里配好 `LIBRARY_SMTP_*`；没配也能先导，
邮件会排队等待，配置好后自动补发——不丢）。

## 4. 迁移的标准流程（推荐按这个顺序）

```
① 备份现状            python app.py backup
② 导出旧系统数据       从旧系统导出 Excel / CSV（UTF-8）
③ 整理表头             按第 2/3 节的表名改好第一行；删掉合并单元格与空列
④ 导入图书            批量导入 → 图书导入 → 预览校验 → 开始导入
⑤ 抽查图书            后台图书列表搜 3–5 个 ISBN，核对册数/位置
⑥ 导入读者            批量导入 → 读者导入 → 预览校验 → 开始导入
⑦ 分批告知初始口令     证号后 6 位；要求首次登录改密
⑧ 重放在借借阅         逐笔「借书」，把借出日期改成真实日期（见 5.2）
⑨ 核对               按第 6 节清单逐项过
⑩ 再备份一次          python app.py backup   ← 迁移完成的「干净起点」
```

**为什么 ④ 在 ⑥ 之前**：读者导入的证号要和馆员账号错开，先把图书导完，
就能在导入读者前专心处理「证号 / 手机号重复」这一类问题，报错信息也更集中。

## 5. 借阅历史：为什么不能导进来

### 5.1 不需要搬的部分

* **已归还的借阅记录**：只影响「历史借阅次数」这类统计，与当前业务（能不能借、
  罚多少、谁在借）完全无关。旧系统的报表继续留在旧系统里备查即可。
* **已收的罚金流水**：同理。系统里的罚金**不落库「应缴额」**，而是由
  `loans` + 逾期天数**实时算出**（`library/fines/service.py`）；把历史收款抄进来
  只会和派生值对不上账（见 `library/db.py` 里 `fine_payments` 的表注释）。
* **已结束的预约 / 赔偿 / 盘点 / 采编单**：都是过程性单据，搬过来是噪音。

### 5.2 必须搬的部分：未还清的借阅

**只有「还没还的书」必须搬**，因为它决定了读者能不能再借、罚多少。

正确做法是**重放业务动作**，而不是往 `loans` 表里灌数据：

1. 后台「借阅管理」→ **借书**，选读者 + 选书 → 系统按 `LIBRARY_LOAN_DAYS` 算出应还日期。
2. 打开该笔借阅，把**借出日期改回真实日期**（后台借阅列表支持编辑日期）。
   * 借出日一改，**逾期天数与罚金自动按统一口径重算**，不用手工填金额。
   * 举例：真实借出日是 40 天前 → 改完立刻显示逾期 10 天、应缴 ¥5.00
     （`LIBRARY_FINE_PER_DAY` × 10，且受 `LIBRARY_FINE_MAX_DAYS` / `LIBRARY_FINE_CAP` 封顶）。
3. 如果这期间旧系统**已经收过一部分罚金**，用「滞纳金管理 → 代收」按实收金额补录一笔，
   把账对上（金额为正，方向由 `payment` / `waiver` 区分）。

> ⚠️ **顺序很关键**：先按「正常日期」办完借阅，**最后**再把日期改到过去。
> 反过来做——读者名下有逾期未还的书时——系统会**拒绝**再给他借新书
> （`BusinessRuleError`，422「有逾期未还图书」），逐笔重放会卡住。

### 5.3 读者照片 / 证件影像

文件本身没法用表格迁。后台「读者附件」支持逐人上传照片（`photo`）与证件影像
（`id_card`），库里只存文件名，实体在 `LIBRARY_UPLOAD_DIR`（默认数据库同级
`uploads/`）。所以**备份要连附件一起打**：

```bash
python app.py backup --with-uploads     # 打成 zip，内含数据库 + uploads/
```

## 6. 迁移完成后的核对清单

| # | 核对项 | 在哪看 | 期望 |
| --- | --- | --- | --- |
| 1 | 书目总数 | 后台概览 / 图书列表底部 | 与旧系统藏书条目数一致（注意：**按种计，不按册计**） |
| 2 | 抽查 5 个 ISBN | 图书列表搜索 | 书名、作者、出版社、位置、总册数逐项对得上 |
| 3 | 读者总数 | 后台概览 / 读者列表 | 与旧系统在册读者数一致 |
| 4 | 抽查 5 个证号 | 读者列表搜索 | 姓名、类型、可借上限对得上 |
| 5 | 手机号重复 | 随机抽一个手机号搜一次 | 只应命中一个读者 |
| 6 | 未还借阅 | 借阅管理 → 在借 | 条数与册数一致，应还日期 = 真实借出日 + 借期 |
| 7 | 逾期与罚金 | 借阅管理 → 逾期 / 滞纳金管理 | 逾期天数与手工算的一致；已收金额与实收一致 |
| 8 | 读者能登录 | 前台 `/reader` 用证号 + 后 6 位登录 | 能进，且被要求改密 |
| 9 | 读者能借书 | 挑一位无逾期读者办一次借→还 | 全程无报错，还书后册数回到原值 |
| 10 | 邮件渠道（可选） | 系统维护 → 邮件渠道 | 配好后点「发送测试邮件」能收到 |

## 7. 常见问题

**Q：提示「CSV 缺少必需的列：书名、ISBN」？**
第一行不是表头，或者表头里有合并单元格导致列名被吃掉。
解决：把表头重新写成第 2.1 节的写法之一，确保每种必需列**只出现一次**。
第一行前面的 BOM、全角空格、零宽字符系统会自动清理，不用手动处理。

**Q：Excel 里 ISBN 变成了 `9.78751E+12`（科学计数法）？**
Excel 把长数字当数值了。导入前把该列设置为**文本**格式，
或在数字前加一个英文单引号（`'9787506365437`）。
`.xlsx` 里如果确实存成了浮点数，系统会去掉无意义的 `.0`
（`2020.0` → `2020`），但科学计数法已经损失了精度，只能回源头改。

**Q：`文件内重复：读者证号 8809001 在前面已出现过`？**
同一份文件里出现了两遍。用 Excel 的「删除重复值」按证号去重，再导一次。

**Q：`手机号 13800009001 已存在`？**
该手机号已经属于另一个读者（或**是馆员账号的登录名**）。要么留空，
要么先处理旧账号。

**Q：`读者类型只能是 VIP/教师/社会/学生 之一`？**
旧系统写的是「研究生」「教职工」这类自定义值。导入前统一映射到这四种之一
（在 Excel 里用查找替换最快）。

**Q：一次导不完怎么办？**
单次上限 1000 行。分批导即可——重复的行会在预览阶段被指出来，
不会因为「已经导过一遍」而全部失败。

**Q：导错了想回退？**
批量导入**没有「撤销」**。回退办法：
① 用 `python app.py restore --from backups/xxx.db` 恢复到迁移前（**须停服**）；
② 或者手工逐条删除刚导进去的记录（后台支持删除书目/读者，
但**被借阅引用过的删不掉**——这是 `ON DELETE RESTRICT` 的保护）。

**Q：`.xls` 提示「另存为 .xlsx」但我没有 Excel？**
用 WPS 打开 → 另存为 → 选「Excel 工作簿（*.xlsx）」；
或另存为 **CSV UTF-8**，走第 2.2 节的第 2 种方式。

## 8. 附录：直接改库（进阶，慎用）

**只有在批量导入覆盖不了、且你清楚风险时**才用它。库里已有的表结构约束
（唯一键、`CHECK`）会挡住大部分手滑，但仍请**先备份**。

### 8.1 先看清表结构

```bash
python - <<'PY'
import sqlite3
from config import get_config
conn = sqlite3.connect(get_config().db_path)
for t in ("books", "members", "loans"):
    print("==", t)
    for row in conn.execute(f"PRAGMA table_info({t})"):
        print("   ", row[1], row[2], "NOT NULL" if row[3] else "", row[4] or "")
PY
```

### 8.2 读者证号整体加前缀（换证规则变了时）

```python
import sqlite3
from config import get_config

conn = sqlite3.connect(get_config().db_path)
conn.execute("BEGIN IMMEDIATE")
try:
    conn.execute("UPDATE members SET card_no = 'X' || card_no WHERE card_no NOT LIKE 'X%'")
    conn.commit()
    print("已加前缀")
except Exception:
    conn.rollback()
    raise
```

> ⚠️ 改证号会让那些用**旧证号登录**的读者登不进来（手机号仍可用）。
> 一次性改完请同步通知读者。

### 8.3 批量补「读者类型」

```python
import sqlite3
from config import get_config

MAP = {"研究生": "学生", "教职工": "教师", "退休": "社会"}
conn = sqlite3.connect(get_config().db_path)
for old, new in MAP.items():
    n = conn.execute("UPDATE members SET member_type = ? WHERE member_type = ?", [new, old]).rowcount
    print(f"{old} → {new}：{n} 条")
conn.commit()
```

### 8.4 改完一定要做的事

1. 跑一遍后台首页，确认概览数字正常（没报 500）。
2. `python app.py backup` 存一份「改完」的快照。
3. 抽查 5 条记录，确认业务视图里显示正常。
