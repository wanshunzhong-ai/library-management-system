# 图书管理系统（Python + Flask + SQLite）

一个开箱即用的图书管理系统，采用 **统一登录入口 + 双端工作台** 的结构：

- **统一登录页（首页 `/`）**：打开网站即是登录页，同一个登录框自动识别身份——读者输借书证号 / 手机号，馆员输工作账号；页面上同时保留图书馆介绍、借阅规则、馆藏推荐 / 新书上架与**免登录的馆藏检索**。
- **读者工作台**（读者登录）：凭读者证号或手机号登录「我的借阅」，查看在借 / 历史 / 逾期与滞纳金，自助续借、维护联系方式与密码；**首次登录强制改密**；还有**站内消息中心**（到书 / 逾期 / 到期前 / 预约过期）、**我的书架**、**评分短评**、**荐购登记**、**资料变更申请**与**电子借书证**。
- **后台控制台**（管理员登录）：图书 / 读者 / 借阅三大业务域 + 预约 / 滞纳金 / 赔偿 / 盘点 / 采编验收 / 批量导入 + 数据概览，全部管理功能在此完成。

无论读者还是馆员，都必须登录才能进入各自的工作台；未登录只能浏览公开的馆藏信息。

纯 Python 标准库 + Flask 单依赖，数据库用单文件 SQLite，无需安装任何数据库服务。

## 快速开始

```bash
# 1. 安装依赖（仅 Flask）
pip install -r requirements.txt

# 2. 启动（首次启动自动建表并创建默认管理员；加 --seed 写入演示数据）
python app.py run --seed

# 3. 打开浏览器
#    统一登录页 http://127.0.0.1:8000/   （首页即登录页，登录框自动识别读者 / 馆员）
#    读者工作台 http://127.0.0.1:8000/reader
#    后台控制台 http://127.0.0.1:8000/admin
```

**默认管理员账号**：`admin` / `admin123`（首次启动时从配置创建，**登录后请立即修改密码**；之后以数据库为准，环境变量不再覆盖）。只要还在用这个默认口令，启动日志会告警、后台控制台顶部会常驻提醒横幅。

**读者账号**：随读者档案自动开通，**初始密码 = 借书证号后 6 位**（如证号 `2024001` → 密码 `024001`）；管理员可在后台一键重置，读者登录后可自行修改。历史数据升级时自动为存量读者回填初始密码。

常用命令：

| 命令 | 说明 |

## 页面与访问规则

| 路径 | 是否需要登录 | 说明 |
| --- | --- | --- |
| `/` | 否 | **统一登录页**：登录框（自动识别读者 / 馆员）+ 简介、推荐、免登录馆藏检索；已登录访问直接跳对应工作台 |
| `/reader` | **读者** | 读者个人中心「我的借阅」，未登录跳回首页登录 |
| `/admin` | **管理员** | 后台管理控制台，未登录跳回首页登录 |
| `/login` `/reader/login` | 否 | 旧登录链接，兼容性 302 到首页 `/` |
| `/api/public/*` | 否 | 门户只读接口 |
| `/api/auth/login` `/logout` `/me` | 否 | **统一登录**、登出、当前管理员会话 |
| `/api/reader/login` `/logout` | 否 | 读者专用登录（兼容保留）、登出 |
| 其余 `/api/reader/*` | **读者** | 个人中心接口，未登录返回 401 |
| 其余 `/api/*` | **管理员** | 图书 / 读者 / 借阅 / 概览，未登录返回 401 |

登录入口全站只有一个（首页）：一份账号密码按"先管理员用户名、后读者证号 / 手机号"的顺序自动识别身份，**一次登录只保留一种身份**（登录会刷新会话），读者与管理员使用各自的 session 键与 CSRF token，互不可访问对方的接口。

## 功能

### 读者账号与个人中心（读者登录）

凭**借书证号或手机号**登录，初始密码为证号后 6 位。**首次登录会被强制改密**——改密前个人中心被一层不可跳过的遮罩挡住，除「修改密码」与「退出登录」外，其余接口一律 403（后端闸门，不是前端遮一下）。登录后可：

- **我的借阅**：在借 / 未归还 / 逾期 / 已归还筛选 + 分页，显示应还日期、续借次数、逾期天数与滞纳金；
- **借阅概览**：在借册数、逾期册数、累计借阅、剩余可借额度、累计滞纳金一目了然；
- **自助续借**：直接续借自己的在借图书（沿用管理端规则：未逾期、未达续借上限、账号未冻结）；
- **我的预约**：查看排队中 / 已到书 / 已借出 / 已取消的预约，显示排队位次与到书时间，可自行取消或**改约到另一本暂无可借复本的书**（改约 = 关旧单 + 开新单，原单转「已取消」保留痕迹）；
- **预约图书**：搜索书名 / 作者 / ISBN / 条码，对**已借完**的书一键加入预约队列（有可借复本时不开放预约，直接到馆借阅即可）；**已到书**的预约会显示**取书倒计时**（保留期内显示「还剩 N 天」，还剩 1 天时高亮），到期未取书由系统惰性扫描自动释放；
- **滞纳金查询与缴纳**：逐笔列出「图书 / 逾期天数 / 应缴 / 已缴 / 待缴」，可单笔缴纳或**一次结清**，并显示缴纳历史；应缴金额实时重算，不存在过期快照；
- **借书证挂失**：证书遗失可一键挂失，挂失期间禁止借书 / 续借 / 预约（已借图书与历史记录不受影响），证件找回或补办后可自助解除；
- **消息中心**：右上角铃铛带未读角标，分「全部 / 未读」页签，聚合四类站内消息——**预约到书**、**逾期催还**、**到期前提醒**、**预约过期释放**，外加**馆员通知**与**审核结果**；单条点开即标记已读、可一键全部已读，点消息卡片可跳到对应模块（白名单锚点）。消息为**惰性生成**（打开时按当前数据补算，无短信 / 邮件网关、无定时任务）；
- **我的书架**：收藏馆藏并写私人备注（备注仅自己可见），可从书架直接跳转检索 / 预约；
- **评分与短评**：对**借过且已归还**的书打 1–5 星并写短评，可修改（同书同人覆盖，聚合取最新）、可删除；聚合评分与最近短评会展示在门户图书详情里（门户只露读者姓氏，不暴露证号）；
- **荐购登记**：提交想看的书名 / 作者 / ISBN / 理由，跟踪「待处理 / 已采纳 / 已驳回」状态并看到馆员答复；
- **资料变更申请**：自助申请修改**姓名 / 读者类型**（读者侧不直接改档案，走馆员审核），同一字段同时只能有一条待审申请；手机号仍可自助直接改（做占用校验）；
- **电子借书证**：个人中心与门户展示**可扫描的二维码 + Code 128 条码**（只编码证号本身，隐私最小化），支持一键打印；
- **维护联系方式**：自行修改手机号与邮箱（手机号可登录，改动会做占用校验；姓名、证号、可借上限只能由馆员维护）；
- **导出 CSV**：借阅记录 / 我的预约 / 我的书架 / 滞纳金四类均可导出（带 UTF-8 BOM，文件名带时间戳）；
- **修改密码**：改后强制重新登录。

账号被冻结的读者仍可登录查看历史借阅，但无法自助续借。越权访问他人借阅记录一律返回 403。

### 读者门户（前台，免登录）

图书馆介绍与借阅规则展示、按分类浏览馆藏、"本馆推荐"与"新书上架"两个书单、关键词 / 分类 / 仅看可借 / **馆藏位置** 四条件检索 + 分页，实时显示每本书的可借状态（可借 N 册 / 仅剩 1 册 / 全部借出）。检索支持按**馆藏条码**直查；书卡与检索结果展示**内容简介摘要**，点击可打开详情弹窗查看简介全文与**可扫描的条码图**；详情弹窗同时展示**读者评分聚合**（平均分 + 评价条数）与**最近短评**（读者姓名只露姓氏，绝不外露证号）。

访客（未登录）还可使用四项自助能力：

- **公告与开馆时间**：首页公告栏展示馆员当前生效的公告（置顶优先、重要公告高亮、过期自动隐藏），「关于本馆」的开馆时间由馆员维护的开馆时间公告覆盖，不用改代码；
- **馆藏分布导览**：按馆藏位置聚合的架位卡片（可借册数 / 在馆种数 / 主要分类），点击任意位置卡检索结果直接过滤到该架位，未标架位的书单独归为一项；
- **在线办证预登记**：访客填写姓名 / 手机号 / 读者类型 / 证件类型与后四位提交申请，拿到 `AC` 申请编号；凭**编号 + 手机号**可随时查询审核进度（通过后显示证号）。这是**预登记而非直接发证**——借书证承载借阅权与责任，必须由馆员审核后发证；
- **免登录借阅速查**：凭借书证号（或手机号）+ 密码查看自己在借几册、几册逾期、待缴罚金、剩余可借额度、最近应还日期，全程只读脱敏（姓名与证号打码）、**不建立会话**，并**复用登录限流计数**——它不能被当成绕过登录锁定的撞库后门。

### 后台控制台（需登录）

**概览**：馆藏 / 可借 / 在借 / 逾期 / 到期 / 读者六项核心指标，近 14 天借阅趋势图，分类借阅排行，热门图书 TOP6，逾期提醒列表。

**图书管理**：新增 / 编辑 / 删除、ISBN 自动规整与唯一校验（**校验位错误时亮黄提示但不阻断保存**，兼容历史条码）、**馆藏条码**（留空自动生成 `BK` 编号，可填馆内已有条码，唯一校验）与**图书简介**（≤1000 字，用于门户展示）、分类与关键词筛选（命中书名 / 作者 / ISBN / 条码 / 出版社）、仅看可借、**表头点击排序**（书名 / 分类 / 出版社 / 年份 / 位置 / 库存，升降序循环并同步 URL）、分页；**下架 / 上架一键切换**（下架后不再对读者展示、不可借出，档案与借阅历史保留，可随时重新上架）；图书详情弹窗展示条码图与简介全文，列表页与详情页均可**批量打印条码标签**（份数默认 = 总册数、三档标签尺寸）；有未归还或历史借阅的图书受删除保护（改用下架）。

**读者管理**：新增 / 编辑 / 删除、证号唯一校验、类型（学生 / 教师 / 社会 / VIP）、冻结 / 恢复、可借上限单独设置、借阅记录弹窗（含累计罚金）；**门户账号列**显示开通状态，新建读者时自动开通并提示初始密码，支持一键重置密码，还可对单个读者**发站内通知**（标题 + 正文 + 可选跳转模块，会出现在读者的消息中心）；**读者附件**：为读者上传**照片**与**证件影像**（JPEG / PNG / WebP / PDF，单文件默认 ≤4MB、每类最多 10 个），弹窗内可缩略图预览、下载与删除——下载走鉴权接口、不生成公开直链。

**借阅管理**：借书（**支持扫码枪直扫馆藏条码自动选中**，或关键词过滤——结果唯一时自动选中；回车链路可走完整单）、还书（自动结算罚金）、**批量还书**（表格勾选多行一次归还，逐条独立事务，成功 / 失败逐条汇总反馈）、续借（限次，冻结读者一律拒绝）、按状态筛选（全部 / 在借 / 逾期 / 已归还）、**表头点击排序**（借出 / 应还 / 归还日期、续借次数、状态、罚金）、逾期天数与罚金自动计算（**封顶记录额外标注「已封顶」**）；删除 / 还书 / 续借等确认框一律显示书名与读者姓名，不再出现内部 ID。**批量催还**：一键给当前逾期清单上的读者各发一条站内通知（可用关键词 / 读者 / 图书先筛选，或传明确 id 列表），**按「借阅 + 应还日期」幂等**——反复点不会刷屏，续借后应还日期变了才会再发一条；**打印催还单**按当前逾期筛选输出一页一张的纸质单据（含逾期天数与滞纳金）；借书成功后可顺带打印**借书凭证**（含书名 / 读者 / 应还日期 / 签字栏）。

**预约管理**：按状态页签（排队中 / 已到书 / 已借出 / 已取消 / 全部）查看预约队列，显示图书、读者、预约时间、排队位次与到书时间；支持**通知到书**（把排队中的预约置为「已到书」，读者在个人中心即可看到提示）与**取消预约**，按书名 / 条码 / 读者 / 证号关键字检索并分页。还书时系统会**自动按序唤醒队列**——某一册归还回补库存后，该书最早的排队预约自动转为「已到书」，无需人工干预。

**办证审核**（读者管理权限）：按待审核 / 已通过 / 已驳回 / 全部页签处理门户提交的办证申请，显示脱敏后的手机号与证件后四位；「通过并发证」弹窗可调整姓名 / 读者类型 / 证号 / 可借上限后一键建档（证号与手机号占用校验与建读者共用同一套，冲突即拦截），发证后提示**证号与初始密码**供转告读者；驳回必须填写原因，原因会展示给申请人。同一手机号已是读者或已有待审申请时，门户端直接拒绝重复提交。

**读者互动**（读者管理权限）：把读者的三类互动收进**一个视图**，页签切换「书评 / 荐购 / 资料变更」——① **书评**：按「全部 / 已发布 / 已隐藏」查看读者评价（含评分、短评、书籍与作者），可置顶 / 隐藏，隐藏后不再计入门户聚合；② **荐购**：按「待处理 / 已采纳 / 已采购 / 未采纳 / 全部」处理，结论必须附答复（后续状态变更同样必填），答复对读者可见；③ **资料变更**：审核读者提交的姓名 / 读者类型变更申请，通过后**回写读者档案**，驳回需填原因。导航入口带**待处理角标**，视图顶部三张小卡汇总待处理数；切换类别时状态页签与默认筛选同步切换。

**公告管理**（公告权限）：维护门户公告与开馆时间，类型分「公告 / 开馆时间」，重要程度分「普通 / 重要」，支持置顶、**生效窗口**（生效时间留空立即生效、失效时间留空长期有效、只填日期则当天结束失效）、草稿 / 已发布 / 已下线状态流转；按状态页签 + 类型 + 标题 / 正文关键词筛选。门户只展示「已发布且在窗口内」的公告，草稿与过期项永不外露。

**滞纳金管理**：缴费流水分页（含收 / 减合计与类型分布）、按读者查看待缴明细；**代收**（部分收款也支持，缺省 = 结清该笔）与**减免**——减免必须填写理由（后端 400 拦截），前端还会再弹一次**二次确认框**把「金额 + 理由」摆在一起请确认，避免误点把该收的钱免掉。所有流水都归属到具体借阅记录，应缴金额永远由 `loans` 实时重算、不落库快照。该视图支持**导出 CSV**。

**赔偿处理**：把「图书本体损失」与「逾期违约金」分开——**罚金按天算，赔偿按书价酌定**，两者可以并存（书逾期又丢了，既要赔书也可能要交滞纳金）。丢书 / 损书各自登记为一张赔偿单（金额、备注），**同一笔借阅同时只能有一张待结案单**（并发下由部分唯一索引兜底）；可按状态 / 类型页签筛选，查看应赔 / 已赔 / 待结金额汇总。结案时可勾选：① **按丢失结案**——把借阅置为已归还但**不回补库存**（书已不在架上），改为总册数 -1、可借数按「总 - 在借」不变式重算，数学上可借数不变；② **同步减免该笔逾期滞纳金**，一次性了结，省得读者为赔书再跑一趟缴费。待结案的单也可以**注销**（登记错了 / 读者找回图书）。该视图支持**导出 CSV**。

**盘点**：按**馆藏位置**（留空 = 全馆）开一张盘点单，单号形如 `PD20261011-001`。开单时把该范围内的图书**快照**进明细（记的是「开单那一刻账上有几册」，而不是实时读库存——否则盘的过程中有人借还，差异报告就失去参照）。明细逐行录入实盘册数，即时算出**账实一致 / 盘盈 N / 盘亏 N** 与进度条，并按差异类型页签筛选；留空表示撤销该项盘点。同一馆位同时只允许一张进行中的单（409）。录完**关闭**盘点单冻结明细（关闭后不能再改实盘数，可重新打开补盘）；**调账**必须先把单关掉、然后再单独确认一次——盘点只负责**发现**差异，改账是另一回事，避免「盘错一次就把库存账改坏」。调账**先全量校验再写入**：任何一项实盘数低于当前在借册数都会被 422 拒绝，且不会留下半截调账。进行中的单可删除，已关闭的单保留作盘点记录。

**采编验收**：登记**到货验收单**（书名 / ISBN / 作者 / 出版社 / 分类 / 年份 / 馆藏位置 / 到货册数 / 单价 / 供应商），此时**还不进馆藏**；列表会提示「馆里是否已有同 ISBN」。验收时按 **ISBN 去重**——已有同 ISBN 就**加册**（总册数与可借数同步 +N，不新增书目），没有才**新建书目并自动分配馆藏条码**；没有 ISBN 又无同书可加册时拒绝验收（不静默丢数据）。可**驳回**（必须写原因）并保留记录；待验收的单可删除，已验收 / 已驳回的保留作采购记录。该视图支持**导出 CSV**。

**批量导入**：图书与读者两大页签，支持**粘贴 CSV**、**选择 .csv / .xlsx 文件**上传（Excel 无需另存，服务端用标准库 `zipfile` + `xml.etree` 解析 .xlsx，**不引入任何第三方依赖**；旧式 `.xls` 会提示先另存为 `.xlsx`），并提供**模板下载**（模板由服务端生成，与解析器共用同一份表头定义，不会各说各话；带 UTF-8 BOM，Excel / WPS 双击即开不乱码）。表头中英文都能认（`书名` / `title`、`读者证号` / `card_no` / `证号`、`馆藏位置` / `位置`…）。流程是**先预览后写入**：预览只做校验（字段、唯一性、**文件内重复**）不落库，把「第 N 行：失败原因」逐行摆出来（失败行标红），确认无误再正式导入。正式导入**逐行独立事务**——单行失败不影响其余行；只有业务错误被记为该行失败，编程错误照旧向上抛（不把 bug 伪装成「数据有问题」）。单次上限 1000 行 / 约 1MB 文本。三种录入方式**共用同一条解析链路**（Excel 先转成 CSV 文本再进同一个解析器），不会出现"粘贴能用、上传不能用"的两套口径。

**审批中心（仅系统管理员）**：当减免金额达到阈值（`LIBRARY_APPROVAL_WAIVER_THRESHOLD`，**默认 0 = 不启用审批**、减免直接生效）时，馆员的减免动作不再立即生效，而是落一张**待审批工单**（谁申请、针对哪位读者哪笔借阅、金额、理由），业务数据**零改动**。系统管理员在这里按待审批 / 已通过 / 已驳回 / 全部页签处理：**通过**会在同一事务内立即执行减免并回报实际减免金额；**驳回**必须填写审批意见、不改任何业务数据。导航入口带**待审批角标**，顶部提示与列表口径一致；工单上同时留住申请理由与审批意见，形成完整的内控留痕。阈值只是一行配置——小馆保持默认即为历史行为，金额敏感的馆把大额减免交给馆长把关。

**系统维护（仅系统管理员）**：三个页签，把三个"运维盲区"搬到界面上。① **后台任务**：后台扫描线程是否在跑、间隔多久、累计跑了多少轮、最近一轮耗时与结果（含「释放预约 / 扫描读者 / 到期提醒 / 逾期提醒 / 邮件投递」五类计数），并支持**立即执行一轮**——不必等下一个间隔，也不必登服务器看日志。每轮结果写入 `job_runs` 表留痕（定时 / 手动分别标记）。② **邮件渠道**：SMTP 渠道状态（配置摘要，**密码永不回传**）、发件地址、待发送 / 已发送 / 发送失败三档计数与最近 15 条出站记录；支持**发送测试邮件**与**一键把发送失败的重置回队列**。未配置 SMTP 时消息照常入队、停在「待发送」，配置好后由后台扫描自动补发——**不丢数据**。③ **数据备份**：列出备份文件（大小、类型、创建时间、各表行数摘要）并提供**下载**；可勾选「连附件一起打包」生成 zip（库 + `uploads/` 一起走，免得恢复后附件全成死链）。备份用 **SQLite 在线备份 API** 做一致性快照，**可以热备、不必停服**。

**浏览状态可分享 / 可回退**：切换视图走 `#hash` 路由并监听 `hashchange`（浏览器前进 / 后退可切换视图）；各视图的关键词 / 分类 / 状态 / 页码 / **排序方向**同步到 URL（`history.replaceState`），**刷新或拷贝链接后筛选与排序均不丢失**。

**导出**：图书管理 / 读者管理 / 借阅管理 / 预约管理 / 滞纳金管理 / 赔偿处理 / 采编验收 / 公告管理 / 办证审核 / 操作日志 / 读者互动共十一个视图的工具栏均有「导出 CSV」，**按当前筛选条件导出全量结果**（自动翻页，上限 5000 行）。文件带 UTF-8 BOM，Excel / WPS 直接打开不出现中文乱码；借阅明细含借出 / 应还 / 归还日期、续借次数、状态、逾期天数与罚金。

**账号管理与操作日志（仅系统管理员）**：后台新增「账号管理」「操作日志」两个视图。账号管理可建号（系统管理员 / 流通馆员）、改姓名与角色、启停用、重置密码、删除——**不能操作自己的账号**、**最后一个在职系统管理员不可被停用 / 降级 / 删除**、用户名不得与读者的借书证号或手机号重名（共用同一登录入口）。操作日志记录每一次后台写操作与登录登出：谁、什么时候、对哪条记录、做了什么、从哪个 IP，越权尝试标「已拦截」；支持按关键词 / 操作者类型 / 动作 / 结果筛选与分页。

### 业务规则

- 借期默认 30 天，最多续借 2 次，逾期罚金默认 0.50 元 / 天（均可配置）。
- **逾期按整日口径判定**：只要「当前日期 > 应还日期」才算逾期，逾期天数 = 自然日之差。因此「状态 = 逾期」与「逾期天数 ≥ 1」永远等价，不会出现「逾期 0 天 / 罚金 ¥0」的自相矛盾（应还当天无论时刻是否已过都仍在借、仍可续借）。
- **罚金有两道封顶**（均按每笔借阅，`0` 表示该维度不限制）：`LIBRARY_FINE_MAX_DAYS` 限制最长计息天数（默认 365 天），`LIBRARY_FINE_CAP` 限制单笔罚金总额（默认 ¥50），两者取先到者。一本书逾期再久也不会罚出天价。
- **罚金只有一个计算口径**：借阅列表、读者个人中心、概览估算三处都调用 `library/fine.py`，逐笔封顶后求和，不再各算各的。
- 有逾期未还、被冻结或已达可借上限的读者不可借书；同一读者不可重复借同一本书。**借书证挂失**与「冻结」是两个正交维度：挂失只拦借书 / 续借 / 预约，不影响查看借阅记录，也不受「未还清不可冻结」的限制。
- **预约规则**：只对**暂无可借复本**的图书开放（有书就直接借，避免队列里塞满本来马上能借到的无效单）；同一读者对同一本书只能有一条未结束预约（`WHERE status IN ('waiting','ready')` 的部分唯一索引兜底，并发下也不会重复排队）。状态机为 `排队中 → 已到书 → 已借出`，另有 `已取消` / `已过期` 两个终态。还书唤队与借出结单都挂在借还路径上，且**失败只告警不抛出**——预约是增强功能，绝不能因为预约表出问题让一次正常的借书 / 还书失败。
- **预约取书保留期**：预约转「已到书」时写入 `expires_at = 当前 + LIBRARY_RESERVATION_HOLD_DAYS`（默认 3 天），读者端显示「还剩 N 天」倒计时。到期释放有**两条触发路径**：后台扫描线程（默认 600 秒一轮，见下）会按时间把超期未取的「已到书」置为「已过期」，读者打开通知中心 / 概览时也会惰性补跑一次——两者都是同一份幂等逻辑，谁先跑到谁生效。过期时同时回补该书队列并给读者发一条「预约已过期」消息。改约读作「关旧单 + 开新单」：原单转「已取消」保留痕迹，新单排队位次按新书重算。
- **首次登录强制改密**：新建读者与「重置密码」都会把 `members.must_change_password` 置为 1，读者登录后被强制改密闸门拦住——`/api/reader/*` 除 `login` / `logout` / `me` / `password` 外全部 403，前端亦弹不可跳过的遮罩；改密成功后标记清零、原会话作废，须用新口令重新登录。读者自助改密（含此闸门路径）同样要求新密码 ≥6 位且不得与旧密码相同。
- **通知在「打开页面」时补算，并另有后台扫描兜底**：消息按当前数据**幂等写入**（`insert_if_absent` 保证同一条业务事件只落一条消息），覆盖预约到书 / 逾期 / 到期前（`LIBRARY_NOTIFY_DUE_SOON_DAYS` 天，0 表示关闭）/ 预约过期四类，外加馆员手动通知与审核结果。触发点有两个：读者打开通知中心 / 概览时的惰性扫描，以及后台扫描线程的**全量扫描**（遍历「当前有未归还借阅」的读者）。
- **邮件出站是可选的第二通道（第 12 批新增）**：站内通知之外，同一个业务事件会**顺带入队一封邮件**——但只在读者**留了邮箱且没关订阅**（`members.email_subscribed`）时才入队，与站内消息互不影响。设计上**入队与投递分离**：入队只写一行轻快的库记录、绝不碰网络；真正的 SMTP 交互由后台扫描线程每轮带一次（也可在「系统维护 → 邮件渠道」手动触发）。**SMTP 未配置时消息停在「待发送」**，配置好之后自动补发，一条不丢。同一业务事件的邮件靠 `dedupe_key` 幂等（部分唯一索引兜底），反复扫描不会轰炸读者；发送失败记 `attempts` 与 `last_error`，重试 5 次后转「发送失败」不再自动重试，管理员可一键把它们重置回队列。用标准库 `smtplib` / `email.message`，**零新依赖**；发信全程 try/except，任何邮件异常都不允许拖垮主业务。读者可在个人中心自行关掉订阅（关掉后仍有站内通知，只是不再发邮件）。
- **罚金减免可走审批（第 12 批新增）**：单笔减免金额达到 `LIBRARY_APPROVAL_WAIVER_THRESHOLD`（**默认 0 = 不启用**、减免直接生效，与历史版本行为完全一致）时，馆员的减免动作**不再立即生效**，而是在**同一个事务内**落一张待审批工单——业务数据零改动。系统管理员在「审批中心」通过时才在同一事务内真正执行减免（按当前待缴裁定实际减免额，已结清则拒绝），驳回只留意见。阈值就是一个开关：对只有一两名馆员的小馆，强制走审批是自我添堵；对减免频次高、金额敏感的馆，把大额减免交给馆长把关是真实的内控需求。
- **备份用 SQLite 在线备份 API，不拷文件**：拷贝一个正在被写入的库有拿到半截事务的风险；在线备份由 SQLite 自己保证快照一致性，而且**不阻塞正在服务的读写**（可以随时热备，不必停服）。备份名带时间戳 `library-YYYYMMDD-HHMMSS.db`，旁边落一份 `.json` 摘要（版本、各表行数、附件文件数）——恢复前先看摘要比看文件名猜要靠得住。**恢复只做冷恢复（CLI 命令，须停服）**，后台只提供「备份 + 下载」不提供在线恢复（把正在运行的库原地换掉是自找麻烦）；覆盖前自动留一份 `library-pre-restore-<时间戳>.db`，恢复错了还能回头——`--yes` 只是跳过交互确认，不是跳过安全副本。`resolve_backup()` 拒绝含路径分隔符或点开头的名字并校验 `parent` 必须就是备份根目录，防路径穿越。
- **评价资格限定「借过且已归还」**：只有对某本书存在已归还借阅记录的读者才能评价该书（防刷分），未借过返回 422；同一读者对同一本书的重复提交是**覆盖**而非新增，聚合展示取最新一条。门户只输出读者姓氏与脱敏姓名，响应体内**不含证号**。
- **资料变更同字段只有一条待审**：读者申请修改姓名 / 读者类型，同一字段同时只能有一条 `pending` 申请（部分唯一索引兜底，重复提交 409）；申请值与原值相同返回 400。审核通过后回写 `members` 档案，驳回必须填写原因并展示给申请人。
- **公告有效期窗口**：门户只展示「已发布 + 生效时间已到 + 失效时间未过」的公告（三个条件缺一不可），置顶优先、其次按开始时间倒序；失效时间只填日期时按**当天 23:59:59** 处理，避免"10-11 失效"在 10-11 当天 00:00 就消失。开馆时间与公告共用一张表、一个口径，只是类型不同、展示位置不同。
- **办证申请防重复**：同一手机号已是读者、或已有待审申请时，门户直接拒绝重复提交（409）；查询进度必须**申请编号 + 手机号双匹配**，防止仅凭编号枚举他人申请。审核发证（建档 + 回写申请）在同一个 `IMMEDIATE` 事务内完成，证号 / 手机号占用校验复用建读者的同一套逻辑。
- **免登录写接口自带限流**：`/api/public/*` 豁免登录与 CSRF，因此两个写接口（办证提交、借阅速查）各自维护 IP 维度的失败计数（默认 10 次 / 锁 10 分钟，`LIBRARY_APPLY_*` 可调）；速查的失败计数**直接复用登录限流的桶**，多试几次速查错误密码同样会触发登录锁定，不存在绕过路径。
- **滞纳金只记「已结算金额」**：应缴金额由 `loans` + `library/fine.py` **实时重算**、从不落库快照，所以配置调整或口径修正后不会留下自相矛盾的旧数据；`fine_payments` 只存已缴纳（`payment`）与已减免（`waiver`）的流水，每笔都归属到具体借阅记录。读者自助缴纳与馆员代收 / 减免走同一套校验（金额必须 > 0 且不得超过该笔应缴），校验与写入同处一个 IMMEDIATE 事务，并发下不会重复缴纳。
- **借阅写路径全程原子**：借书的校验（逾期 / 可借上限 / 重复借）与写入在同一个 `BEGIN IMMEDIATE` 事务内完成，并发请求被串行化；库存扣减用条件 UPDATE（`WHERE available_copies > 0`），还书只在真正把记录置为已归还时才回补库存且不超过总册数，续借把次数上限直接写进 `WHERE`。数据库层另有唯一索引与 CHECK 约束兜底 —— 并发下不会超借、不会重复在借、库存不会越界。
- **下架**（总册数 = 0）要求该书当前没有在外借出的册数；任何时刻都保证 `可借数 = 总册数 - 在借数`，调整总册数的校验与写入同处一个 IMMEDIATE 事务。下架图书从读者门户的检索、新书榜、分类与统计中整体隐藏。
- 删除保护：图书 / 读者存在借阅记录时禁止删除，避免破坏流通档案（图书改用下架）。
- **赔偿与罚金分开**：罚金是**逾期违约金**（按天 + 双重封顶，`library/fine.py` 唯一口径），赔偿是**图书本体损失**（金额由馆员酌定）；两者可以并存，结案时可选择一并减免该笔逾期罚金。**同一笔借阅同时只能有一张待结案赔偿单**（`WHERE status='pending'` 的部分唯一索引兜底，并发下不会重复登记）。**按丢失结案不回补库存**：借阅置为已归还（字面是"结清这笔借阅"而非"书回来了"），总册数 -1、可借数按 `总 - 在借` 重算 —— 结案前后可借数不变（少的那册本来就借在外面、本来就不在架上），若核销后总册数会小于在借册数则直接拒绝。
- **盘点只发现差异，改账要单独确认**：开单时把应盘册数**快照**进明细（不是实时读库存），否则盘的过程中发生借还，差异报告就失去参照。同一馆位同时只允许一张进行中的盘点单；已关闭的单冻结明细、不可删除（保留作盘点记录），但可重新打开补盘。调账必须先关闭盘点单，且**先全量校验再写入**——任何一项实盘数低于该书当前在借册数都会整体拒绝，不会留下半截调账。
- **采编验收按 ISBN 去重**：馆里已有同 ISBN 就**加册**（`total_copies` 与 `available_copies` 同步 +N），没有才新建书目并自动分配 `BK` 条码。到货单在验收前**不进馆藏**，验收 / 驳回后不可删除（保留采购记录）；没有 ISBN 又无同书可加册时拒绝验收，不静默丢数据。
- **批量导入逐行独立**：每一行是一次独立的创建调用，单行失败不影响其他行；只有业务错误（`AppError`）被记为该行失败，编程错误直接向上抛（不把 bug 伪装成"数据有问题"）。预览（`dry_run`）只调用与正式写入**完全同一套**的 `validate_*`，不做"预览说没问题、真导入却报错"的两套口径；**文件内重复**（同一份 CSV 里出现相同 ISBN / 证号 / 手机号）单独提示，避免与"库里已存在"混淆。单次上限 1000 行 / 约 1MB。
- **读者附件四道防线**：① 扩展名白名单（JPG / PNG / WebP / PDF）；② **魔数嗅探**（改扩展名伪装会被识别为"声明与内容不符"并拒绝）；③ 磁盘文件名由服务端 `secrets.token_hex` 生成、完全不用用户提供的名字（`../../app.py` 这类文件名无写文件机会）；④ 读取时校验拼出的绝对路径仍在上传根目录内。附件**不做公开直链**，下载必须登录后台（`Cache-Control: no-store`）。每类最多 10 个，单文件上限 `LIBRARY_UPLOAD_MAX_MB`（默认 4MB）。
- **后台定时扫描线程**：`LIBRARY_SWEEP_INTERVAL_SECONDS`（默认 600 秒，**0 = 不启动**）驱动一个 daemon 线程，按间隔跑「预约过期释放」+「全量到期 / 逾期提醒」。**只在 `app.py run` 的进程里启动**（`create_app(with_scheduler=True)`），测试与嵌入式用法默认不起线程；轮次异常只告警、绝不让线程死掉；两条扫描都是幂等的（条件 UPDATE + `dedupe_key` 唯一索引兜底），因此多实例部署下重复触发只是几次空查询。**没有引入任何任务队列 / 调度框架**，若需要"严格只跑一次"，应改由外部调度（cron / Celery beat）调用。

### 馆藏条码与图书简介

- 每本书都有独立的**馆藏条码号**（默认 `BK` + 7 位序号，如 `BK0000006`），与 ISBN 解耦；可手工改为馆内已有条码（4–32 位字母 / 数字 / 连字符，全局唯一）。
- 条码图由 `static/js/barcode.js` 在前端生成 **Code 128** SVG（零依赖，码表已与 `python-barcode` 独立实现逐位比对一致），可直接扫码。
- 每本书都有**简介**字段（≤1000 字），后台表单可编辑；门户书卡 / 检索详情、后台图书列表与详情弹窗均会展示。
- 老库自动升级：`init_db` 幂等迁移加列、为存量图书回填条码并建唯一索引、把历史越界库存夹回总册数（并发重复回补可能造成的 `可借数 > 总册数`）；演示书目按 ISBN 自动回填简介（只补空值，不覆盖已录入内容）。
- 借阅记录（后台借阅列表、读者"我的借阅"、借书 / 还书提示）均带条码号，便于按条码上架归位与扫码核对。

### 安全与鉴权

- **双身份体系**：统一入口自动识别读者 / 馆员；管理员与读者使用各自的会话键与 CSRF token，一次登录只保留一种身份；读者端接口强制只读写本人数据，跨读者访问返回 403。
- **密码存储**：PBKDF2-SHA256 加盐哈希，绝不落明文；读者初始密码 = 证号后 6 位，登录后可改，管理员可重置。
- **会话**：基于 Flask 签名 Session；Cookie 标记 `HttpOnly` / `SameSite=Lax`（启用 HTTPS 后可开 `Secure`），有效期默认 8 小时，登录成功后轮换会话（防会话固定）。
- **CSRF**：写操作（POST / PUT / DELETE）需带 `X-CSRF-Token`，管理员与读者各用独立 token，使用 `hmac.compare_digest` 常量时间比对。
- **会话密钥**：`LIBRARY_SECRET_KEY` 留空时**自动生成随机密钥并保存到数据目录的 `.secret_key`**（每套部署一份、权限 600、已在 `.gitignore`）；显式配置示例值或过短的密钥时，生产模式（`LIBRARY_DEBUG=false`）直接拒绝启动 —— 密钥可预测意味着任何人都能伪造管理员会话。
- **登录限流**：管理员与读者**共用同一套计数**（防止交替调用入口绕过锁定）。失败同时记进 `账号 + IP` 与 `IP` 两个桶：前者连续失败 5 次锁定 5 分钟，后者阈值更宽（×5）专门挡同一来源轮换账号名的密码喷洒。**只有来自 `LIBRARY_TRUSTED_PROXIES` 的请求才采信 `X-Forwarded-For`**，且从右向左取第一个非受信地址，直连部署时一律用真实对端 IP —— 否则换个伪造请求头就是一个新桶，锁定形同虚设。
- **登录标识全局唯一**：证号与手机号都能当登录账号，因此两者不得互相重复、也不得与后台管理员工号重名（管理员建档 / 改档、读者自助改手机号三条路径共用同一校验 + `members(phone) WHERE phone <> ''` 部分唯一索引兜底），否则统一入口会出现身份归属不确定。
- **默认口令提醒**：管理员仍在使用配置里的初始口令时，启动日志给出告警，后台控制台顶部常驻醒目横幅并提供一键改密入口。
- **访问隔离**：后台页面与全部管理接口统一守卫，未登录一律拒绝；接口返回 401 JSON，页面 302 跳统一登录页，登录后按身份落回原目标。
- **角色权限（RBAC）+ 操作审计**：**读写能力分开声明**（第 12 批把 7 项能力扩到 12 项：`book:read` / `book:write`、`member:read` / `member:write`、`loan:read` / `loan:write`、`announcement:read` / `announcement:write`、`dashboard:read`、`approval:approve`、`account:manage`、`log:read`），**连 GET 查询接口也逐个挂上读能力校验**——只隐藏前端入口、接口却不校验，等于没做权限（抄个 URL 就能把全馆读者名单拉走）。系统管理员持全部能力；流通馆员持除 `approval:approve` / `account:manage` / `log:read` 外的全部（含全部读能力），因此**看不到审批中心与系统维护**，手改地址栏 / 直接请求接口都会拿到 403。越权返回 403 并写一条「已拦截」日志；**所有后台写操作（图书/读者/借还/账号/登录登出/改密）都会在 `operation_logs` 表留痕**——谁、什么时候、对哪条记录、做了什么、从哪个 IP，日志表只记动作与目标 id，不复制业务字段（避免把个人信息再抄一份）。前端按权限隐藏无权入口，手改地址栏也会被挡回概览；但后端独立校验，前端只是"不给入口"。
- **安全头**：CSP、X-Frame-Options、nosniff、Referrer-Policy；`/admin`、`/reader` 与 `/api/*` 响应禁止缓存。

## 技术要点

- **并发安全**：借阅写路径统一用 `BEGIN IMMEDIATE` 事务把「读-判断-写」串行化（默认的 deferred 事务读的是旧快照，并发下会被绕过）；配合条件 UPDATE + 命中行数检查、`loans(book_id, member_id) WHERE returned_at IS NULL` 部分唯一索引、`available_copies <= total_copies` CHECK 约束三层兜底，WAL 模式减少读写锁冲突。`db.check_consistency()` 可随时对账库存区间、重复在借与总量。
- **类型化错误**：`ValidationError(400) / UnauthorizedError(401) / NotFoundError(404) / ConflictError(409) / BusinessRuleError(422)`，全局处理器统一输出。
- **可观测性**：单行 JSON 日志（含 request id、路径、状态码、耗时），登录成功 / 失败 / 锁定均有审计日志，`/health` `/ready` 探针。
- **安全**：PBKDF2 密码哈希、签名会话（密钥自动生成且不可预测）、CSRF 双提交校验、双维度登录限流（且只采信受信代理的 XFF）、登录标识全局唯一、SQL 参数绑定、前端全量 HTML 转义（防 XSS）、CSP / X-Frame-Options / nosniff 安全头、显式白名单 CORS（默认关闭）。
- **数据体检**：`db.check_consistency()` 对账库存区间、重复在借、库存总量、重复手机号与登录标识遮蔽，`python app.py check` 一键查看、`python app.py repair` 修复有明确答案的问题。
- **跨模块事务**：参与外层 `BEGIN IMMEDIATE` 的写入一律走「接收调用方连接」的仓储方法（`insert_conn` / `add_copies_conn` / `insert_payment_conn` 等），因为 `db.execute()` / `db.transaction()` 自带事务，在外层事务里调用会**中途提交外层事务、悄悄破坏原子性**（例如「赔偿结案 + 同步减免罚金」必须同时成功或同时不发生）。
- **文件上传**：扩展名白名单 + 魔数嗅探 + 随机存储名 + 路径归属校验四道防线；`MAX_CONTENT_LENGTH = (LIBRARY_UPLOAD_MAX_MB + 1)MB` 只做粗粒度兜底，精确的体积判定在服务层，避免超大请求直接灌进内存。
- **后台定时扫描**：`library/scheduler.py` 是最朴素的 daemon 线程（固定间隔 + `threading.Event` 停止），**刻意不引入任务队列 / 调度框架**——代价是多实例下会重复触发（两条扫描均幂等，重复只是几次空查询），收益是零依赖、无运维负担、测试里默认不启动。
- **前端**：无框架原生实现，防抖搜索、分页、弹窗表单、字段级错误提示（**报错自动聚焦并滚动到出错字段**）、**列表加载态骨架 + `aria-busy`**、可手动关闭 / 悬停暂停 / 带 `role` 的统一 Toast、空列表带「清除筛选」引导、SVG 手绘趋势图；视图切换、筛选条件与**排序状态**同步 URL（可刷新 / 可分享 / 支持前进后退）；弹窗有**焦点陷阱**（Tab 循环不逃逸、关闭后焦点归位）且 label 自动关联控件；**≤900px 侧栏横向化为顶部导航**的移动端适配；会话临期自动亮出「保持登录 / 重新登录」提醒横幅。**条码（Code 128）与二维码（QR Model 2）均由前端自实现零依赖生成**（`static/js/barcode.js`、`static/js/qrcode.js`），可直接扫码。门户与管理台样式各自独立，共享 `site.css` 设计令牌；`site.css` 统一兜底 `[hidden]{display:none !important}`（否则被作者样式设过 `display` 的元素会覆盖 UA 规则、导致 `el.hidden = true` 仍被渲染）。

## 已知限制

- 单机单文件 SQLite，适合中小规模（校园 / 班级 / 小型机构）；如需多人并发写入建议迁移 PostgreSQL（Repository 层已隔离，替换成本低）。
- 登录限流为进程内计数，多进程 / 多实例部署时需改用 Redis 等共享存储。
- **后台已分两级角色**：`系统管理员`（全权，含**审批中心**、账号管理与系统维护、操作日志）与`流通馆员`（图书编目、读者档案、借还续借、**公告与开馆时间**、概览报表、滞纳金代收与减免；**不能审批减免、不能管理账号、也看不到全量日志与系统维护**）。权限按能力（capability）声明在 `library/auth/permissions.py` 的映射表里（12 项，读写分开），路由用 `@require_permission(...)` 标注，**连 GET 查询接口也逐个校验读能力**，未知角色一律拒绝。
- **备份可热备，恢复必须停服**：备份走 SQLite 在线备份 API（不阻塞读写），后台可一键生成与下载；但**恢复只提供 CLI 命令**（`python app.py restore --from ...`，须先停服务），后台刻意不给在线恢复入口。覆盖前会自动留一份 `library-pre-restore-*.db`。跨机器的整站迁移请用 `--with-uploads` 把附件一起打走（附件只在库里存文件名）。
- 待办：分馆授权与调拨、只读审计/财务岗位、MARC / ISBN 自动抓取、服务端 PDF 生成（见 `docs/优化评审.md` 的「已评估、不做及原因」）。
- 读者自助续借沿用管理端规则（未逾期、未达上限、未挂失、未冻结）。
- 罚金仅做估算与结算展示，未接入支付网关；读者「自助缴纳」与馆员代收都是**线下收款 + 系统登记**，缴费后如需凭证请走馆内流程。导出为纯前端生成 CSV，超大数据量（>5000 行）需改用后端流式导出。
- **站内消息仍是主渠道，邮件是可选的第二通道**：第 11 批补上了 `library/scheduler.py` 后台扫描线程（预约过期释放 + 全量到期 / 逾期提醒，默认 600 秒一轮），第 12 批补上了 **SMTP 邮件出站**（`LIBRARY_SMTP_*`，不配也能跑：消息照常入队、停在「待发送」，配置好后自动补发）。**短信 / 微信 / 钉钉仍未接入**；且线程只在 `app.py run` 的进程里跑（`LIBRARY_SWEEP_INTERVAL_SECONDS=0` 可退回纯惰性模式）。读者完全不打开页面、又没配邮件时，触达仍只到「站内消息已生成」这一步。
- **批量导入支持 .xlsx 但有边界**：`.xlsx` 走**标准库零依赖解析**（`zipfile` + `xml.etree`），只读**第一张工作表**，不处理公式、图表、合并单元格与多 sheet 选择（合并单元格会让后续列错位，导入前请先取消合并）；只认 `.xlsx`，**不吃老式 `.xls`**（会提示另存为）；单次上限 1000 行 / 约 1MB，更大的历史数据迁移需分批或改用后端脚本。借阅历史 / 罚金流水不做批量导入是有意为之（见 `docs/历史数据迁移.md`）。
- **打印是浏览器排版**（`#printLayer` + `@media print`），无服务端 PDF 生成：借书凭证 / 催还单 / 条码标签都依赖浏览器打印对话框，且未做纸张尺寸的精细适配（A4 可用，票据机需自行调缩放）。附件上传只做「类型 + 大小 + 魔数」校验，**未做病毒扫描 / 图片再编码**。
- **盘点调账只改总册数与可借数**，不做"按册"级别的单册条码台账（系统里 `total_copies` 是计数而非逐册记录），因此无法定位"具体哪一册不见了"。
- **电子借书证二维码由前端自实现**（`static/js/qrcode.js`，QR Model 2 字节模式、版本 1–10、L/M/Q/H、自动掩码；`selfTest()` 6/6 通过，已与 `segno` 逐模块比对一致），**未引入任何第三方依赖**；二维码只编码读者证号本身，不含姓名 / 手机号等个人信息。
- 门户登录提示已不再公开「初始密码 = 证号后 6 位」的推导规则（改为「由馆员告知」），并已实现**首次登录强制改密**；但顺序证号在首次登录前仍可能被离线猜解（新读者 + 重置密码都会重新置位强制改密标记）。
- 会话到期提醒按「最后一次请求」计算闲置时长，仅在管理端实现；读者门户长时间挂起时仍会静默失效。
